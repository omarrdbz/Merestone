# AI-055 — Negotiated MCP capabilities and requests to the client

Revision 1.0.0 · MCP · TEST

## Objective and risk

Verify negotiated MCP capabilities and requests to the client.
An unagreed capability is used or data/actions are delivered outside the consent.

Controls: CTL-CONSENT

## Applicability

One alternative must be satisfied: mcp_client **o** mcp_host

Actor: Actor with access to negotiated versions and capabilities, limited to the authorized environment.

Access: gray-box; access limitations are recorded without inferring PASS

## Preparation

- Negotiated versions and capabilities; fixture server; sampling/elicitation only if enabled
- Current charter, limits and telemetry defined.

Allowed baseline: Equivalent operation on an allowed fixture, with a documented expected result.

Restricted control: Restricted operation without an adversarial technique; document the control's decision.

## Procedure

1. Freeze versions, state and policy; run the allowed baseline.
2. Record the handshake, capabilities and policy of each role.
3. Request a non-negotiated or out-of-purpose capability with synthetic data.
4. If there is sampling/elicitation, observe context selection, consent, destination and returned data.
5. Keep traces, restore fixtures and check queues/residual state.
